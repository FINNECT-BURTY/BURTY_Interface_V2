# BURTY 마이데이터·오픈뱅킹 직접 등록 가이드

> **문서 목적**: BURTY 서비스를 **전문기관 위탁 없이** 마이데이터 사업자로 직접 등록하고, **금융결제원(KFTC)** API(마이데이터·오픈뱅킹)를 신청·연동하기 위한 실행 가이드입니다.  
> **대상 독자**: 사업·법무·개발 담당자  
> **작성일**: 2026.06.15  
> **프로젝트**: BURTY Interface (Spring Boot 4 / Java 21)

## 1. 개요

BURTY는 다음 두 축의 금융 API가 필요합니다.

| 축 | 역할 | 규제·등록 |
|----|------|-----------|
| **금융 마이데이터** | 계좌·카드·대출 등 **통합 조회**, 전송요구·동의 | 금융위 마이데이터 사업자 등록 → 금융결제원 API |
| **오픈뱅킹** | 잔액·거래내역 조회, **이체(출금)** | 금융결제원 오픈뱅킹 이용기관 등록 (별도) |

**직접 등록**이란, 마이데이터 전문기관에 API를 위탁하지 않고 **BURTY 운영 법인**이 금융위에 사업자로 등록하고, 금융결제원과 직접 연동하는 방식을 말합니다.

> 개별 은행(카카오뱅크, KB 등) API는 오픈뱅킹으로 대부분 커버됩니다. 은행별 직접 제휴는 오픈뱅킹 이후 특수 기능이 필요할 때만 검토하세요.

## 2. 등록 구조 이해

```
┌─────────────────────────────────────────────────────────────────┐
│                    BURTY 운영 법인                                │
├─────────────────────────────────────────────────────────────────┤
│  ① 금융위원회  마이데이터 사업자 등록                              │
│  ② 금융결제원  마이데이터 API (전송요구·인가·조회)                 │
│  ③ 금융결제원  오픈뱅킹 이용기관 (조회·이체)                       │
│  ④ 본인확인사업자 (NICE / KCB / Pass 등) — ③·② 공통 전제          │
│  ⑤ (해당 시) ISMS / ISMS-P, 전자금융 관련 검토                    │
└─────────────────────────────────────────────────────────────────┘
         │                              │
         ▼                              ▼
   [정보제공자]                    [참가은행]
   은행·카드사 등                  오픈뱅킹 망
```

### BURTY에서의 역할 분리

| API 종류 | BURTY 용도 | 주요 코드 |
|----------|-----------|-----------|
| 마이데이터 | 현금흐름 예측, 자산 요약, 고정지출 학습 | `MyDataOAuthAdapter`, `MyDataApiAdapter` |
| 오픈뱅킹 조회 | 거래 동기화, 잔액 확인 | `OpenBankingApiAdapter`, `TransactionSyncBatch` |
| 오픈뱅킹 이체 | 사용자 이체 실행 | `OpenBankingApiAdapter`, `TransferService` |

## 3. 사전 요건

### 3.1 법인·사업

| 항목 | 요구 수준 | 비고 |
|------|-----------|------|
| 법인 사업자 | **필수** | 개인사업자는 마이데이터 사업자 등록이 사실상 어려움 |
| 사업자등록 업종 | IT·소프트웨어, 데이터/금융 관련 | 사업계획서와 일치 필요 |
| 서비스 도메인 | HTTPS 운영 (`burty.co.kr` 등) | Redirect URI 등록용 |
| 전자금융 해당 여부 | 이체 제공 시 검토 | 전자금융거래법·감독규정 검토 권장 |

### 3.2 인력

심사 시 제출·확인되는 대표 인력:

- 정보보호 책임자(CISO) 또는 전담자
- 마이데이터·개인(신용)정보 보호 담당자
- 시스템 개발·운영 담당자

### 3.3 보안·인증

| 항목 | BURTY 현황 | 심사 대응 |
|------|-----------|-----------|
| 전송 구간 암호화 | TLS (nginx) | 인증서·HSTS 운영 |
| 저장 시 암호화 | `FieldEncryptor` (토큰) | 키 관리 절차 문서화 |
| 인증 상태 공유 | Redis (`burty.redis.enabled`) | prod 필수 (`ProdStartupValidator`) |
| 감사 로그 | `AuditLogger` | 보관 기간·열람 절차 명시 |
| ISMS / ISMS-P | 별도 취득 필요 | **직접 등록 시 사실상 필수에 가깝게 요구** |

### 3.4 제출·운영 문서 (초안 필요)

- 마이데이터 사업계획서
- 서비스·화면 설명서
- 개인정보 처리방침
- 마이데이터 **정보전송요구·수집·이용 동의서** (결제원 표준 양식 기준)
- 정보전송 철회·파기 절차서
- 정보보호 대책서, 장애·유출 대응 매뉴얼
- 전산시설·네트워크 구성도 (EC2, Docker, MariaDB, Redis, nginx)

## 4. 마이데이터 직접 등록 절차

### 4.1 전체 흐름

```
[준비] 법인·문서·ISMS
    ↓
[금융위] 마이데이터 사업자 등록 신청
    ↓
[심사] 서면·현장 (시스템·인력·보안)
    ↓
[등록 완료] 사업자 코드 발급
    ↓
[금융결제원] 마이데이터 포털 — 이용기관·API 신청
    ↓
[테스트베드] 연동·시나리오 통과
    ↓
[운영 전환] 운영 API 키·실거래
```

### 4.2 금융위 등록 — 대표 제출 서류

- 법인등기부등본, 사업자등록증
- 정관, 주주명부
- 마이데이터 사업계획서
- 정보보호 관리체계 설명서
- 개인정보 영향평가서 (해당 시)
- 전산시설·네트워크 구성도
- 테스트베드 연동 계획서

**예상 기간**: 서류·심사 포함 **6~12개월+** (ISMS 미보유 시 더 소요될 수 있음)

### 4.3 금융결제원 마이데이터 API

등록(또는 등록 진행 중) 이후 포털에서 진행:

| 단계 | 작업 |
|------|------|
| 1 | 이용기관 등록 → Client ID / Secret 발급 |
| 2 | Redirect URI 등록 |
| 3 | 이용 API 신청 (전송요구, 인가, 토큰, 자산 조회 등) |
| 4 | 테스트베드 E2E 통과 |
| 5 | 운영 심사·운영 전환 |

**BURTY Redirect URI (운영 예시)**

```
https://burty.co.kr/api/v1/mydata/oauth/callback
```

### 4.4 사용자 플로우 (FE + BE)

```
1. GET  /api/v1/mydata/institutions/{institutionCode}/authorize?userId={id}
       → 인가 URL 반환
2. 사용자: 은행/카드사 앱·웹에서 동의
3. Callback → authorization code 수신
4. POST 토큰 교환 (MyDataAuthService)
5. 자산·계좌 조회 (MyDataApiAdapter)
6. GET  /api/v1/cashflow/forecast 등 BURTY 서비스 API
```

### 4.5 규제상 필수 기능 (코드 보강 필요)

| 기능 | 설명 | BURTY 현황 |
|------|------|-----------|
| 정보전송요구 | 사용자가 특정 기관·항목 전송을 요청 | **미구현** |
| 동의 | 표준 동의서·버전·시각 기록 | 앱 약관만 (`ConsentRecord`) |
| 철회 | 전송요구·동의 철회 및 이력 | 부분 (`ConsentManagementService`) |
| 전송 로그 | 송수신 내역 보관 | `AuditLogger` 일부 |
| 토큰 관리 | 기관별 access/refresh, 만료 갱신 | `TokenStore` + `MyDataTokenRefreshBatch` |
| 기관별 연동 | 기관 코드별 OAuth | `MyDataInstitutionController` (골격 있음) |

## 5. 금융결제원 오픈뱅킹 API 등록

마이데이터와 **별도 신청**이며, **병행 진행** 가능합니다.

### 5.1 신청 흐름

```
[오픈뱅킹 포털] 이용기관 가입 (법인 인증)
    ↓
서비스·이용 목적 등록
    ↓
API 권한 신청
    ↓
테스트 환경 (testapi.openbanking.or.kr) 연동
    ↓
운영 심사 → 운영 키 발급
```

### 5.2 API 권한 — 단계적 신청 권장

| 단계 | API | BURTY 사용처 |
|------|-----|-------------|
| **1차** | 계좌목록, 잔액, 거래내역 | `OpenBankingApiAdapter`, `TransactionSyncBatch` |
| **2차** | 이체(출금), 2차 인증(ARS/OTP) | `ExternalFinanceService`, `TransferService` |

2차(이체)는 본인확인·이상거래·한도·감사 요건이 더 엄격합니다. BURTY의 WebAuthn, 일일 이체한도(`TransferLimitGuard`), 가족 알림은 심사에 유리합니다.

### 5.3 BURTY 오픈뱅킹 엔드포인트 (설정 기본값)

| 용도 | 설정 키 | 기본 URL (테스트) |
|------|---------|-------------------|
| 계좌목록 | `burty.external.open-banking-accounts-url` | `https://testapi.openbanking.or.kr/v2.0/account/list` |
| 잔액 | `burty.external.open-banking-balance-url` | `.../account/balance/fin_num` |
| 거래내역 | `burty.external.open-banking-transactions-url` | `.../account/transaction_list/fin_num` |
| 이체 | `burty.external.open-banking-transfer-url` | `.../transfer/withdraw/fin_num` |
| 토큰 | `burty.external.open-banking-token-url` | `https://testapi.openbanking.or.kr/oauth/2.0/token` |

### 5.4 사용자 동의 플로우 (보강 필요)

오픈뱅킹은 **사용자별** `fintech_use_num`(핀테크 이용번호)과 **동의 redirect**가 필요합니다. 현재 BURTY는 서버 측 토큰 위주이므로, 실연동 전 **OAuth 콜백 컨트롤러·FE 동의 화면** 구현이 필요합니다.

## 7. 환경 설정

### 7.1 운영 (prod) — 실연동 시

```properties
# 마이데이터
burty.mydata.stub-mode=false
burty.mydata.client-id=${MYDATA_CLIENT_ID}
burty.mydata.client-secret=${MYDATA_CLIENT_SECRET}
burty.mydata.redirect-uri=https://burty.co.kr/api/v1/mydata/oauth/callback
# authorize-url, token-url, asset-url 은 금융결제원 명세서 URL로 설정

# 오픈뱅킹
burty.external.stub-mode=false
burty.external.open-banking-client-id=${OB_CLIENT_ID}
burty.external.open-banking-client-secret=${OB_CLIENT_SECRET}

# 인프라 (필수)
burty.redis.enabled=true
burty.security.field-encryption-key=${BURTY_FIELD_ENCRYPTION_KEY}
spring.jpa.hibernate.ddl-auto=validate
```

### 7.2 개발 (dev)

```properties
burty.mydata.stub-mode=true
burty.external.stub-mode=true
burty.redis.enabled=false
spring.flyway.enabled=false
```

### 7.3 테스트

```properties
spring.jpa.hibernate.ddl-auto=create-drop
spring.flyway.enabled=false
burty.api.rate-limit.enabled=false
```

## 9. 병행 일정 (예시)

| 시기 | 사업·행정 | 개발 (BURTY) |
|------|-----------|--------------|
| **0~1개월** | 법인 확인, 약관·동의서 초안, ISMS 컨설팅 착수 | 전송요구·동의 엔티티 설계 |
| **1~2개월** | 오픈뱅킹 **조회 API** 이용기관 신청 | `LinkedInstitution` 동기화 |
| **2~4개월** | 금융위 마이데이터 사업자 신청 | 테스트베드 연동 (stub → 실) |
| **4~6개월** | 서면·현장 심사 | 오픈뱅킹 사용자 동의 플로우 |
| **등록 후** | 결제원 마이데이터 운영 전환 | 전송 로그·모니터링 |
| **안정화 후** | 오픈뱅킹 **이체** API 신청 | 2차 인증·이체 E2E |

> **대회·데모만** 목표: stub 모드 + 본 가이드의 문서·아키텍처로 설계 완성도를 보여주고, 실연동은 등록 진행 중 테스트베드 영상·시나리오로 대체할 수 있습니다.
